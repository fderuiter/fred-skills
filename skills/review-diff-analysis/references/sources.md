# Research references

Reviewed 2026-11-18. Use these as differential review methods, not evidence about an uninspected diff.
Verify language scoping and dispatch semantics before drawing caller-impact conclusions.

- [Google Engineering Practices — What to Look for in a Code Review](https://google.github.io/eng-practices/review/reviewer/looking-for.html): Functional correctness, caller interactions, edge cases, and test alignment in change review.
- [Alberto Bacchelli & Christian Bird — Expectations, Outcomes, and Challenges of Modern Code Review](https://dl.acm.org/doi/10.5555/2486788.2486882): Empirical failure modes when reviewers inspect diff lines without surrounding context.
